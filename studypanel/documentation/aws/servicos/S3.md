# S3 — Simple Storage Service

**Incidência:** 🔴 Muito Alta | **Domínio:** Storage

---

## Conceito

S3 é o armazenamento de objetos da AWS. Armazena qualquer tipo de arquivo com durabilidade de 11 noves (99.999999999%).

Analogia: S3 é um Google Drive na nuvem — mas infinitamente escalável, sem gerenciar servidores.

---

## Conceitos Fundamentais

- **Bucket**: container global onde os objetos ficam (nome único global)
- **Objeto**: arquivo + metadados (até 5TB por objeto)
- **Key**: caminho do objeto dentro do bucket (ex: `fotos/2024/perfil.jpg`)
- **Region**: bucket criado em uma região específica
- **Durabilidade**: 99.999999999% (11 noves)
- **Disponibilidade**: varia por classe de storage

---

## Classes de Storage

| Classe | Uso | Recuperação | Custo |
|--------|-----|-------------|-------|
| **S3 Standard** | Acesso frequente | Imediato | $$ |
| **S3 Intelligent-Tiering** | Acesso imprevisível | Imediato | $$ + fee |
| **S3 Standard-IA** | Acesso infrequente | Imediato | $ |
| **S3 One Zone-IA** | Infrequente, sem HA | Imediato | $ |
| **S3 Glacier Instant** | Arquivamento acessado raramente | Milissegundos | $$ |
| **S3 Glacier Flexible** | Arquivamento (minutos a horas) | 1-5 min ou 3-5h | $ |
| **S3 Glacier Deep Archive** | Arquivamento de longo prazo | 12-48h | $¢ |

## Segurança

### Bucket Policy
- Política JSON no nível do bucket
- Controla acesso de usuários, contas e serviços

### ACL (Access Control List)
- Legado, use bucket policies em vez disso
- Controla acesso a nível de objeto

### Block Public Access
- Configuração que impede acesso público (ativado por padrão)
- Deve ser desabilitado explicitamente para sites estáticos

### Presigned URL
- URL temporária com acesso ao objeto sem autenticação
- Expiração configurável (segundos a horas)
- Ideal para compartilhar objetos privados por tempo limitado

---

## Versionamento e Lifecycle

### Versionamento
- Mantém múltiplas versões de um objeto
- Proteção contra deleção acidental
- Quando habilitado, deletar = criar marcador de deleção

### Lifecycle Rules
- Transição automática entre classes de storage
- Expiração automática de objetos ou versões antigas

Exemplo típico:
```
0 dias → S3 Standard
30 dias → S3 Standard-IA
90 dias → S3 Glacier Flexible
365 dias → S3 Glacier Deep Archive
730 dias → Deletar
```

## Replicação

| Tipo | Uso |
|------|-----|
| **CRR (Cross-Region Replication)** | DR, compliance, latência global |
| **SRR (Same-Region Replication)** | Ambientes separados, compliance |

Requisito: **Versionamento habilitado em ambos os buckets**

## Funcionalidades Avançadas

### S3 Event Notifications
- Trigger para Lambda, SQS, SNS quando objeto é criado/deletado
- Ideal para processamento automático de uploads

### S3 Transfer Acceleration
- Upload acelerado via CloudFront edge locations
- Paga por aceleração utilizada

### Multipart Upload
- Upload de arquivos grandes em partes paralelas
- Recomendado para arquivos >100MB, obrigatório >5GB

### S3 Select / Glacier Select
- Consultas SQL em arquivos CSV/JSON sem baixar o arquivo inteiro

## Configuração de Website Estático

1. Ativar "Static website hosting" no bucket
2. Desabilitar "Block public access"
3. Criar bucket policy para acesso público
4. (Opcional) Usar CloudFront na frente para HTTPS e performance

---

## Pegadinhas da Prova

1. **Nomes de bucket são globalmente únicos** (mas o bucket fica em uma região)
2. **S3 não é por AZ** — é regional com replicação automática em ≥3 AZs
3. **Read-after-write consistency** — disponível para todos os objetos
4. **Glacier não é acessível imediatamente** (exceto Instant Retrieval)
5. **Presigned URL** expira — o acesso é temporário
6. **MFA Delete** protege deleção permanente de objetos versionados
7. **S3 Object Lock** previne modificação ou deleção (WORM)
8. **CORS** deve ser configurado no bucket, não no CloudFront

## Caso Real

### Spotify
Armazena bilhões de arquivos de áudio no S3 com Intelligent-Tiering. As músicas mais populares ficam no Standard; menos acessadas migram automaticamente para Standard-IA.
